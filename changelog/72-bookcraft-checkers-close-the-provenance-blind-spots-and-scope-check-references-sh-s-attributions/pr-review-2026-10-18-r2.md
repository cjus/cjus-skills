### What is working well

- **The Critical fix is the minimal correct one.** `paths = [p for p in visible_md[source] if
  p != f.resolve()]` compares resolved paths on both sides, because `visible_md` stores
  `p.resolve()`. "Nothing else carries the name" goes to `exempted` with its own reason, so it
  counts toward `n_elsewhere` and qualifies the banner as `OK*` instead of reading as a pass. The
  `len(paths)` counts now say how many files were actually read.
- **The sentence fix aims at the actual cause.** `REF.sub(" ", between)` removes the token that
  introduced the false boundary, and the fixed-width lookbehinds handle `e.g.`/`i.e.`/`cf.`/`vs.`
  without a second pass. Both compile and run under 3.9.25.
- **The blank-declaration guard sits in the right place.** It runs before the `cited_as` test,
  so a template line fails the file with its line number. `(default)` alone is caught too,
  because `DEFAULT` strips it to `""`.
- **The unclosed-fence REVIEW reuses `Fence`** through the new `opened_at`, rather than adding a
  second fence reader. It also catches the case the branch's own CommonMark rule creates: a
  four-backtick fence that a `` ``` `` line does not close.
- **Answering the two questions conservatively was the right call.** `§ 2` against `2.1`/`2.2`
  resolves again, as it did on `main`, while `§ 1` still never resolves against `10.`. A key row
  resting on a reference whose book was inferred now REVIEWs, matching check 1.
- **The fixture suite grew with the fixes**: `self-named`, `blank-name` and `unclosed` were
  added, along with three new assertions in `two-books.md` (lines 24, 26 and 28) and the
  provenance `§ 20` case.

#### Suggestions

🟢 **The CHANGELOG says `§ 1` never resolves against `1.20`, and it does**

📍 Location: `changelog/72-*/CHANGELOG.md`, the "review's two questions" bullet of the
2026-10-18 22:40 entry

**What I see:**
"`§ 2` resolves against a source that heads only `2.1` and `2.2` again ... `§ 1` still never
resolves against `10.` or `1.20`."

**The risk:**
The subsection rule this same bullet introduces is `m.group().startswith(want + ".")`, and
`"1.20".startswith("1.")` is true, so `heading_hit("§ 1", {"1.20 later"})` returns True (probed).
The code's own docstring states the case that does hold, "`§ 1.2` is never `1.20`". The
CHANGELOG is the record a later reader trusts about what the matcher refuses, and this line
describes a refusal that does not exist.

**Suggested fix:**
"`§ 1` still never resolves against `10.`, and `§ 1.2` never against `1.20`."

**Learning note:**
When a rule is loosened on purpose, the sentence that sums it up has to be re-derived from the
new code, not carried over from the old one.

🟢 **`check-provenance.sh`'s fence-aware tag definitions have no fixture, though the CHANGELOG
says every addressed item does**

📍 Location: `check-provenance.sh:1785-1787`, `fixtures/provenance/`

**What I see:**
`defined.update(refs.tag_paragraphs(p.read_text()))` replaced the line-by-line `TAGDEF` reader.
That changes a verdict: a mark citing a tag that appears only on a fenced line passed on `main`
and now FAILs (probed). Nothing in `fixtures/provenance` holds a fence. The CHANGELOG entry
opens "each has a fixture case in `fixtures/attribution` or `fixtures/provenance`", and this
item, folded in from round 1's DROP, is the exception.

**The risk:**
Low. The change delegates to a shared, already-exercised function, and it moves in the strict
direction. But if someone later swaps the call back, the verdict moves with no test to notice,
and the CHANGELOG's claim is not quite true today.

**Suggested fix:**
Append to `provenance-fixture-02-one-of-each-failure.md` a fenced `[2-9] ...` line and a
paragraph whose mark cites `[2-9]`, then raise the manifest row to 8 failures. Or reword the
CHANGELOG to exclude this item.

**Learning note:**
Scope folded in late tends to skip the evidence rule that the planned work followed.

**Scope note, not a finding.** Round 1 marked this fold-in DROP. Bringing it in grows the PR
past its objective, though only slightly. It is correct, small and strict, so I would keep it
rather than revert it. Its only cost is the missing fixture above.
