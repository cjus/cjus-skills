## PR review: bookcraft checkers: close the provenance blind spots and scope check-references.sh's attributions

Ticket: #72-bookcraft-checkers-close-the-provenance-blind-spots-and-scope-check-references-sh-s-attributions
(consolidating #51 and #65). Reviewed: `main..0deaaca` plus the uncommitted `visible_md`
change in `check-references.sh`. No PR is open yet; this is the first review on the branch.

### Summary

The branch fixes `units_of()` so a mark after a blank line covers its paragraph, makes a
bare-number `§ N` match its number exactly, adds one CommonMark `book_model.Fence` that every
fence reader in both checkers calls, and teaches `check-references.sh` to attribute citations
by a per-file `<!-- cites: -->` declaration and `book.json` `cited_as`, and to read a
file-sourced quotation against the file it names. The objective is that each check either does
the work it reports or names what it skipped. Most of it does. One new path reports work it
did not do.

### What is working well

- **`Fence` is small, correct and actually shared.** All five fence readers (`units_of`,
  `declarations`, `blocks`, `tag_paragraphs`, `tag_citations`) call it, so step 5's "agree on
  what a fence is" holds by construction, as D1 asked. The backtick-in-info-string rule and
  the at-least-as-long closer are both right, and the indentation trade-off is stated where
  it is made.
- **`units_of()`'s `closed` flag is the minimal fix.** A blank closes the unit without
  discarding it, and only the next unit's first line drops it. Headings, fences and marks
  still reset. That is exactly R9.
- **`Attribution` keeps the undeclared path inert.** With no declaration, `patterns` is
  empty, every reference comes back `(m, "", "default")`, and `whose == attr.this` is always
  true. The undeclared reading is preserved by structure, not by a flag.
- **`attribution()` refuses a declaration it cannot read**, as a FAIL naming the file,
  instead of falling back to the undeclared reading. That is the right direction.
- **The report keeps count-and-name for every class**: `filed` lists found and not-found
  quotations, `exempted` lists unreadable ones, `other_tags`/`other_cites` list another
  book's citations, and the `(of this book: ...)` qualifier stops "every" from overreaching.
- **The `bj` NameError fix** is a real latent crash on `main`, caught in passing and recorded.
- **The uncommitted `visible_md` change is correct and should be committed.** The committed
  version called `setdefault` before `is_file()`, so a directory named `x.md`, or a referring
  argument that does not exist, put a basename in `visible_md` with an empty path list. A
  quotation naming it then landed in "could not be read" (an exemption) instead of the
  chapter path. The fix moves in the strict direction the comment above it promises.

### Issues found

#### Critical

🔴 **A quotation attributed to a file sharing the referring file's name is always "found", in the referring file itself**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-references.sh:866-870`, `:1083-1097`

**What I see:**

```python
for p in [*search_root.rglob("*.md"), *(pathlib.Path(a) for a in rest[1:])]:
    ...
held = [t for t in map(file_text, visible_md[source]) if t is not None]
...
found = any(nq in t for t in held)
```

`visible_md[source]` includes the referring file whenever its basename equals the named
source, and the referring file contains the quotation by construction, since that is where
the quotation is written.

**The risk:**
A new book's `OUTLINE.md` quoting the superseded book's `OUTLINE.md` (the case
`createbook/SKILL.md § When the book supersedes one that already exists` describes), or any
`README.md`/`NOTES.md` quoting another of the same name, reports `found in OUTLINE.md` and the
run prints a plain `OK`. The other file is never actually what matched. On `main` the same input
printed `OK*` and named the quotation as never checked. So the branch turns an honest skip into
a false pass, which is the one outcome the objective ("does the work it reports or names what it
skipped") exists to remove. Confirmed by probe: the quoted sentence was in neither
`sources/a/shared-notes.md` nor `sources/b/shared-notes.md`, and the run said found.

**Suggested fix:**
Leave the quoting file out of its own candidates, and treat "nothing else carries the name" as
an exemption rather than as a read:

```python
here = f.resolve()
paths = [p for p in visible_md[source] if p != here]
if not paths:
    # The file names itself: its own text holds the quotation by construction.
    exempted.append((f.name, where, f"{source}, which is the quoting file itself"))
    n_elsewhere += 1
    continue
held = [t for t in map(file_text, paths) if t is not None]
```

Use `len(paths)` in the "read all k files" counts, and reword the `n_elsewhere` banner clause
("sourced to a file this run could not read") so it covers both reasons. Add a fixture case:
`referring/x/shared-notes.md` quoting `shared-notes.md` with text in neither source.

**Learning note:**
When a check reads a corpus to confirm a claim, the claim's own text must not be in the corpus.
Otherwise the check is a tautology that still prints a green line.

#### Important

🟡 **The sentence test reads `ch.` and `e.g.` as sentence ends, so a same-sentence missing chapter only REVIEWs**

📍 Location: `check-references.sh:203` (`SENTENCE_END`), `:315-316` (`Attribution.refs`)

**What I see:**
`between = text[b:m.start()]`, then `SENTENCE_END = [.!?](?=\s|$)`. In
`The Field Guide's ch. 1 and ch. 8 both cover it.`, the text between the name and `ch. 8` is
`'s ch. 1 and `, and the period in `ch.` matches.

**The risk:**
D3 and `createbook/SKILL.md:827` both say a missing chapter FAILs when the name shares its
sentence. `ch. N` is the first form `REF` accepts, and a list of chapters after one name is
the common way to write it, so every reference after the first in such a list is demoted to
REVIEW. The run then exits 0 under `OK*` instead of 1. `e.g.`, `i.e.`, `cf.` and `vs.` do the
same. Confirmed by probe (lines 4 and 6 REVIEW, the `chapter`-spelled control on line 8 FAILs).

**Suggested fix:**
Mask what is known not to end a sentence before testing:

```python
ABBREV = re.compile(r"\b(?:ch|e\.g|i\.e|cf|vs)\.", re.I)
gap_text = ABBREV.sub(" ", between)
out.append((m, book, "block" if SENTENCE_END.search(gap_text) else "sentence"))
```

Add `The Field Guide's ch. 1 and ch. 8` to `two-books.md` as a FAIL assertion.

**Learning note:**
A boundary detector has to know its own grammar's tokens. Here `REF` itself introduces the
false boundary.

🟡 **An empty `<!-- cites: -->` declaration moves every citation in the file to a book named ""**

📍 Location: `check-references.sh:223-227` (`declarations`), `:243-248` (`name_pattern`), `:346`

**What I see:**
An empty name survives `declarations()`. `name_pattern("")` compiles to
`(?<!\w)(?!\w)`, which matches zero-width at almost every position, so `names_in` returns a
span next to every reference, and `refs()` gives each one to book `""`.

**The risk:**
A declared file with a placeholder `<!-- cites: -->` line (a template, a half-edited header)
exits 0 with a plain `OK` over a missing chapter and a misquote. Both are listed only as
`chapter 8 of ` with a blank book name. Confirmed by probe. This is malformed input, but
`attribution()` exists to refuse malformed declarations, and this one gets through.

**Suggested fix:**
In `attribution()`, before the `cited_as` test:

```python
blank = [i for n, _, i in decl if not n]
if blank:
    return None, f"line {blank[0]} declares a book with no name"
```

**Learning note:**
An empty string compiled into a pattern does not match nothing. It matches everywhere.

#### Suggestions

🟢 **An undeclared file no longer reads "exactly as before": check 1 now sees a reference wrapped across a line**

📍 Location: `check-references.sh:920-922`, with `REF`'s `\s*` at `:93`

Check 1 moved from lines to `blocks()`, so `chapter` at the end of one line and `8` at the
start of the next is now a reference. On `main` it was not (probe: references 0 and exit 0 on
`main`, a FAIL and exit 1 on the branch). The new behaviour is the more correct one, and it
matches what check 2 already saw. But the CHANGELOG ("No other output moved for an undeclared
file except the reworded REVIEW paragraph"), the `Attribution` docstring and `SKILL.md:827`
("as before") say otherwise. Keep the behaviour and correct the claim. One line in NOTES.md
and the CHANGELOG covers it.

🟢 **The "nothing quotes the book" note is suppressed by another book's chapter references, not only its quotations**

📍 Location: `check-references.sh:1292-1293`

`not other_cites` is true for a declared file that only *references* the companion's chapter,
with no quotation anywhere, so the note that check 2 had nothing to examine goes missing
(probe `p-gate`). The comment above the gate lists "one of another book" as a *quotation*.
Count other-book quotations separately (`n_other_quotes`) and gate on that.

🟢 **An unclosed fence in a referring file now silently hides checks 1 and 2 after it**

📍 Location: `book_model.py` `Fence`, and its callers in `check-references.sh`

A fence nothing closes runs to end of file, which is CommonMark and right. On `main`, check 1
had no fence reading and check 2's `blocks()` read through one. Now both stop at a stray
opening, and only the counts drop. `check-book.sh` fails an unclosed fence in a chapter, but
nothing does for a referring file. A one-line REVIEW after the loop when `fence.opening is not
None` would name the skip. Cheap, and it is the objective's own rule.

🟢 **Docs: two behaviours a user will hit are not in `createbook/SKILL.md`**

📍 Location: `createbook/SKILL.md:818-827`

(a) A file-sourced quotation is read against *every* visible file with that basename, per D4.
The SKILL text says "that file". (b) A declared file whose names include none of this book's
`cited_as` FAILs unread. The `book.json` table row documents only the missing-`cited_as` case.
One clause each.
