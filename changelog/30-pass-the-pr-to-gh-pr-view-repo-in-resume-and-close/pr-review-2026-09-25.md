## Issues found

### Critical

🔴 **The pre-test review file would publish two banned project names when the close commits
it**

📍 Location:
`changelog/30-pass-the-pr-to-gh-pr-view-repo-in-resume-and-close/pr-review-2026-09-24.md:84`.
The file is untracked, and close step 7's `git add <changelogRoot>/<slug>/` stages it.

**What I see:**
The Repo rules paragraph quotes the CLAUDE.md banned-term audit regex word for word, inside
backticks, to show which pattern it ran. Most of that regex's alternatives are obfuscated
(`.?`, character classes). **The fourth and seventh are not: they are two of the banned project
names, spelled out in lowercase.** The case-insensitive audit matches that line and nothing else
on the branch.

**The risk:**
- **The PR would regress the default branch.** `main` returns zero hits for the audit today, and
  so does `HEAD`. Step 7 commits the whole plan folder and pushes, and merging #38 would put two
  banned names into a public repo's history.
- **CLAUDE.md is local for this exact reason.** `.gitignore` keeps it out of the repo because it
  "holds the cross-project reference rules, which name the very projects this repo must not
  mention". An audit regex is a list of those names.
- **Removing it later is expensive.** It would take a history rewrite, and the repo has already
  been rebuilt once to scrub these terms.
- **The noise lasts.** Every later audit of the repo would hit this line, and a check that
  always fires teaches people to ignore it.

**Suggested fix:** before step 7, change line 84 so it names the pattern without reproducing it.
For example:

```markdown
**Repo rules.** The case-insensitive banned-term audit (the pattern in the local CLAUDE.md)
found nothing.
```

Then re-run the audit over the plan folder and expect zero hits. This review file refers to the
pattern the same way on purpose. Only this one line needs changing: the code, `PLAN.md`,
`CHANGELOG.md` and the summary are all clean.

**Learning note:** a scanner's search list is itself a copy of the thing it scans for. Report
*that* you ran the check and what it found, and point to where the pattern lives. Never paste it
into an artifact that ships. The reviewer brief supplied the pattern inline, and the earlier
review echoed it as evidence. That was a reasonable instinct, but it breaks a rule for
confidential names.
