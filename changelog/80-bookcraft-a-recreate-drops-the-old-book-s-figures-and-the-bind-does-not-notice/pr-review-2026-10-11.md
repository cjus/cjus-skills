#### Suggestions

**1. The warning prints under the `slides:` heading, and reads as part of the slides report**

Location: `plugins/bookcraft/skills/makebook/scripts/build-book.py`, `main`, the
`figure_record_missing` block placed after the `if slides:` block.

**What I see:** with the README removed from the guide fixture, the report reads:

```
figures: 1, list on page 3
slides: 1 lesson-script slide(s), set at 62% measure, not numbered and not on the Figures page
  warning: no diagrams/README.md in the book folder, so this book's figure decisions were never recorded (1 figure(s) placed).
```

**The risk:** in the case this warning targets, a freshly recreated book, `figures` is empty, so
no `figures:` line prints, and step 4 has just copied the slides. The two-space indented warning
then sits directly under `slides: N lesson-script slide(s)`, the one thing the recreate did carry
across. A reader skimming the report can take it as a note about the slides.

**Suggested fix:** move the block up to sit between the `if figures:` block and `if slides:`.
Where figures exist it then reads under `figures:`. Where none exist, print a heading line first
so the warning always has a parent, for example:

```python
if figure_record_missing(src):
    if not figures:
        print("figures: 0")
    print(f"  warning: no {FIGURE_RECORD} in the book folder, ...")
```

**Learning note:** in an indented report, indentation is grammar: a reader attaches an indented
line to the heading above it. A new line belongs under the heading it is about, and it should
still have one when that heading's own block is skipped.

**2. The two skills name different numbers as "the candidate count"**

Location: `plugins/bookcraft/skills/createbook/SKILL.md § Recreating a book`, gate bullet 4 and
the "Hand that pass" paragraph. `plugins/bookcraft/skills/makebook/SKILL.md § Deciding where a
figure helps`, the "A book that replaces an earlier edition" paragraph.

**What I see:** the createbook gate counts the images the old *chapters* reference, plus inline
`<svg>`, and says "this is the count the figure pass answers to". The makebook paragraph draws
its candidates from the old *README* ("Each figure it records"), and the placed-again and
passed-over sum must "add up to the candidate count". It also applies only "Where the operator
names the old book's `diagrams/README.md`", while createbook covers a missing README with "the
candidates are the figures the gate counted".

**The risk:** the two numbers diverge when the old README drifted from the old chapters, for
example after a figure was added in a later revision without a README entry. A figure the old
chapters placed but the old README never recorded is then no candidate in makebook's terms. The
sum still adds up, and the figure leaves by drift, which is the exact outcome the
redraw ruling exists to prevent. The gate does show both numbers, so an attentive operator can
catch the mismatch. That is why this is a suggestion rather than Important.

**Suggested fix:** one sentence in each skill. At the createbook gate: "Where the README and the
chapters disagree, name each figure in one and not the other: every one of them is a candidate."
In makebook: "...read it after step 1, together with any figure the old chapters place that it
does not record. Where the old book has no README, the candidates are the figures the
recreate's gate counted."

**Learning note:** when one count is handed off between two documents, define it in one place
and cite it from the other. Two near-synonyms ("the figures the old book placed" and "the
candidates") stay in sync only until the first edge case.

**3. The `assertions.json` half of the scope is untested**

Location: `build-book.py:figure_record_missing`, the
`or (src / "assertions.json").is_file()` clause. `bind/run.sh`.

**What I see:** the guide fixture has a `book.json` and no `assertions.json`, and appendix-slug
has neither. A mutation that deletes the `assertions.json` clause passes all 22 assertions.

**The risk:** low. A folder with `assertions.json` and no `book.json` exists only between
`/createbook`'s step 1 and step 4, when nobody binds. The clause is close to unreachable, which
is also the argument for not spending a fixture on it.

**Suggested fix:** either accept it as is and note in the docstring that the `book.json` half is
the one the suite pins, or cover it for free. Drop an `assertions.json` into the
`appendix-table` copy before its bind, and assert the warning there. That bind has no other
figure-related assertion, and no extra render is needed.

**Learning note:** a disjunction with two clauses needs a case per clause, or a mutation of
either clause has to fail something. The author's two mutations pinned "fires" and "scoped",
but "scoped by which file" is a third axis.

**4. Step 4's "copy that folder into the new one" can be read as changing the path**

Location: `plugins/bookcraft/skills/createbook/SKILL.md § Recreating a book`, the step 4 row.

**What I see:** "copy that folder into the new one unchanged".

**The risk:** read literally as `cp -R <old>/diagrams/slides <new>/`, it lands at
`<new>/slides`, and the carried-over key still names `diagrams/slides`. That is the same
dangling key the row exists to prevent. "Unchanged" most likely means the contents, not the
path.

**Suggested fix:** "copy that folder to the same path in the new one, unchanged".

**Learning note:** an instruction an agent executes as a shell command should name the
destination path. Prepositions like "into" carry a different meaning to `cp` than to a reader.
