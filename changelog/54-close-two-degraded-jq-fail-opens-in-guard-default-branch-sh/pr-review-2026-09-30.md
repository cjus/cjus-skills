## PR review: [#54] Close two degraded-jq fail-opens in guard-default-branch.sh

Reviewed 2026-09-30 against `main` @ `a26f79c`, branch head `df75cf4` (one commit), draft PR #57.
This is the first review on this branch. There is no prior `pr-review-*.md` in this folder. The
settled `## Deferred` items from `changelog/1-guard-default-branch-sh-under-matches-a-truncated-payload-when-jq-is-absent/`

### Summary

The no-jq branch now matches `GIT_VERB_RAW`, which is `GIT_VERB` widened with a JSON-escape class
at `git`'s leading boundary, in every whitespace run, and after the verb, where the string's
closing `"` is also accepted. A jq that is on `PATH` but cannot run is caught after a failed parse
by `jq -n true` and routed to the no-jq branch. `gate()` falls back to `printf` whenever
`jq -nc` prints nothing, and it swaps a reason it cannot escape for a fixed one. Both
fail-opens named in the objective are closed, and each is pinned by probes that fail without it.

### What is working well

- **The widening is additive, and I could not break it.** Every group in `GIT_VERB_RAW` is
  `GIT_VERB`'s with alternatives added and none removed, so the "matches everything GIT_VERB
  does" claim holds by construction. That is the right shape for a path whose contract is "never
  under-matches".
- **Handing only jq-cannot-run to the no-jq branch, not every failed parse, is well judged.** The
  trailing-comma probe pins exactly the mistake the broader version would make. The comment
  explains why the narrower test was chosen.
- **`gate()` is now a real chokepoint.** "No route through gate() may end without a decision,
  whatever its jq does" is stated, implemented, and pinned by the half-broken-jq stub. The
  quoted `-C` case pins the swap.
- **The evidence is unusually good.** It includes a mutation table, measured failure shapes, and
  a documented rejection of decoding with timings. The README's new shapes reproduce exactly (see
  below).
- **The `pj` refactor pays for itself.** Its "not JSON reads as `<none>`, never as pass" rule
  means a broken decision cannot masquerade as no decision.

### Independent verification (all on macOS, `/bin/bash` 3.2.57, jq 1.8.2)

Fixtures, scripts and outputs are in this session's scratchpad under `rv/`: `setup.sh`,
`lib.sh`, `probe1.sh` to `probe4.sh`, `gen2.mjs`, `diff2.sh`, `matrix.sh`, `sens.sh`,
`shapes.sh` and `perf2.sh`.

- **Suite.** 113 of 113 passed. Against `main`'s hook the suite gives
  `passed 98, failed 15, skipped 0  (113 cases)`, matching the CHANGELOG.
- **Differential, stricter than the author's.** The jq side used the hook's real semantics:
  line-wise `grep -E "$GIT_VERB"` on the decoded command, then line-wise `grep -E "$ALLOW_TOKEN"`.
  The no-jq side used `ALLOW_TOKEN_RAW`, then `GIT_VERB_RAW`, on the raw payload. All four regexes
  were lifted from the branch hook.
  - The alphabet covered all of ASCII 0x01 to 0x7F, plus NBSP, NEL, U+2028, U+2029, U+3000,
    U+FEFF, U+1680, U+2003, a surrogate pair, a lone surrogate, U+FFFD, a C1 control and
    escape-lookalike sequences.
  - There were three encoders: `JSON.stringify`, all non-ASCII as `\u`, and `/` as `\/`.
  - Across 2 seeds × 2 locales × 15,000 commands per encoder, that is 180,000 checks with
    **0 verb under-matches**.
  - **The harness is sensitive.** On 3,000 cases, `main`'s raw `GIT_VERB` gives 53 under-matches
    and `GIT_VERB_RAW` without the closing-quote alternative gives 32. The branch gives 0.
- **Real hook, targeted boundaries** (`probe1.sh`). Characters 0x01, 0x08, VT, FF, CR, 0x1C,
  0x1F, DEL, NBSP, U+3000, U+2028, NEL, `"`, `\`, `)`, `>`, backtick and `'` were each placed
  before `git`, between `git` and the verb, after the verb, and inside an option run. CRLF lines,
  a leading newline and a trailing newline were also tried. **Nowhere did jq say `ask` while
  the no-jq or broken-jq path passed.**
- **README shapes.**
  - With a broken jq: 35/78 outside a configured repo and 8/105 inside one.
  - With a missing jq (a links-only `PATH` with no jq at all): the same 35/78 and 8/105.
  - Outside a configured repo, exactly the four degraded-section cases the README names pass.
- **Silent exit 0.** I found no route with jq present, missing, broken (exit 126) or failing only
  in `gate()` that exits 0 silently on a default-branch commit or push.
- **Reclassification steering.** `jq -n true` reads no input, and `INPUT=$(cat)` has already
  drained stdin, so payload bytes cannot reach it. I sent ten malformed payloads through a working
  jq: a trailing comma, a trailing `,`, an invalid `\x` escape, trailing garbage, single quotes,
  20,000-deep nesting, a truncated object, a top-level array, `NaN` and a BOM.
  - Every payload gives the same decision as on `main`.
  - Eight are denied. `NaN` and the BOM pass, because jq 1.8 accepts both and parses them.
- **`gate()` fallback.** With a jq that fails only on `-nc`, I tried reasons holding `"`, `\`,
  0x01, DEL, NEL, `%s%n`, a quote in a configured token name, and bypass mode. Every output was
  one line that strict `JSON.parse` accepts, carrying a decision.
- **Cost** (`perf2.sh`). Eight new 1MB shapes aimed at `RAW_ESC` all stayed roughly linear. The
  worst was 0.42s, against 0.04s for `main`'s regex. There is no pathological growth anywhere near
  a hook timeout.

#### Suggestions

🟢 **"0.32s at worst" is the worst of six shapes, not a bound**

📍 Location: `plugins/pr/hooks/guard-default-branch.sh:L378-L379`, and
`changelog/54-.../CHANGELOG.md:L64-L65`

**What I see:**

```
# path that runs for every Bash call. This regex was measured at 0.32s at worst on a
# 1MB payload built to stress it.
```

**The risk:**
A 1MB body of `git \t-a\tb\t` (escapes as JSON writes them) took 0.42s here (`perf2.sh`,
`SIZE=1000000`). Nothing breaks, but this file's header says reading it is not evidence, and a
number stated as "at worst" invites a later editor to treat it as a ceiling.

**Suggested fix:**
Write "measured at under 0.5s on 1MB payloads built to stress it", or name the shapes.

**Learning note:**
A stress measurement bounds the inputs you tried, so phrase it as a finding about those inputs
rather than as a guarantee.

---

🟢 **Phrase the `gate()` swap as "prove safe, else swap", and keep the recovery when the token
name is safe**

📍 Location: `plugins/pr/hooks/guard-default-branch.sh:L167`, `L201-L205`

**What I see:**

```
JSON_UNSAFE='["[:cntrl:]]|\\'
...
if [[ $reason =~ $JSON_UNSAFE ]]; then
  reason="... jq failed while building the full reason."
  [[ "$decision" == "deny" ]] && reason="${reason} STOP and ask the operator in conversation."
fi
```

**The risk:**
There are two small risks, and neither is reachable in any setup I could build:

1. **The test detects the unsafe case.** If `=~` fails to evaluate, the reason goes through
   unswapped. bash 3.2 under a UTF-8 locale returns no match for `a"<0xff>` against
   `JSON_UNSAFE` (`probe3.sh`, last line), which is the settled #1 limitation. A reason
   carrying such bytes would need a branch name that APFS refuses to create ("Illegal byte
   sequence", `probe4.sh`) and a jq that fails only in `gate()`.
2. **The deny swap drops the approval-token instruction**, even when the token name is not what
   made the reason unsafe. The comment just above says a degraded path should keep the recovery.

**Suggested fix:**

```
JSON_SAFE='^[^"\\[:cntrl:]]*$'
...
if ! [[ $reason =~ $JSON_SAFE ]]; then
  reason="The default-branch commit guard needs operator approval for this commit or push. jq failed while building the full reason."
  if [[ "$decision" == "deny" ]]; then
    reason="${reason} STOP and ask the operator in conversation."
    tok="${ALLOW_NAME:-$ALLOW_NAME_DEFAULT}"
    [[ $tok =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]] &&
      reason="${reason} Only if they approve, re-run the command prefixed with ${tok}=1. Never add that yourself."
  fi
fi
```

On bash 3.2 the whitelist form swapped every unsafe and every undecidable string in `probe4.sh`.

**Learning note:**
In a fail-closed path, write the test so that an engine error lands on the safe branch. "Match
the safe shape or else" fails closed; "match the dangerous shape or else" fails open.

#### ⏭️ Deferred to follow-up

These do not affect the verdict. Both are pre-existing, since `main` gives the same result, and
neither is worsened by this PR. They are also pre-existing correctness gaps in a guard whose
degraded path documents "never under-matches". The scope contract's unconditional rule files
such gaps immediately, as #54 itself was, so triage should consider that before DROP.

- **Without jq, the approval token is honoured across a newline inside an assignment value.**
  - **Where:** `guard-default-branch.sh:L344-L345` (`ALLOW_TOKEN_RAW`).
  - **Why:** its `[^[:space:]]*` reads the two characters of the escape `\n` as a value, so
    `PR_ALLOW_MAIN=1 X=`⏎` git push origin main` passes. The jq path asks, because the token
    and the push sit on different lines.
  - **Theme:** degraded-path under-matches.
  - **Symptom:** with jq missing or broken, a push on the line after an indented token-and-assignment
    line runs unprompted.
  - **Occasion:** the next edit to the no-jq token pattern or to `GIT_VERB_RAW`.
  - **Repro:** `probe1.sh` row "token then assignment ending in NL" gives `jq=ask nojq=pass
    badjq=pass | main: nojq=pass`.
- **`GIT_VERB`'s trailing class rejects `)`, `>` and a backtick, so a default-branch push passes
  on every path, jq included.**
  - **Where:** `guard-default-branch.sh:L51`.
  - **Examples:** `(cd /x && git push)`, `echo $(git push)`, `git push>/dev/null`.
  - **Theme:** GIT_VERB boundary coverage.
  - **Symptom:** an agent's ordinary subshell spelling pushes the default branch with no prompt.
  - **Occasion:** the next change to `GIT_VERB`. `GIT_VERB_RAW` must be widened in step, as its
    comment says.
  - **Repro:** the last four rows of `probe1.sh` pass on all four columns.

Checked and dropped, noted here so that they are not re-tested:

- **An `ALLOW_NAME` inherited from the environment.** `main`'s no-jq path emitted invalid JSON
  for `ALLOW_NAME='X"Y'`. The branch's swap now makes the output valid, so this PR improves it.
- **U+2028 inside a `-C` path.** The jq path passes it too.
- **Encoders that `\u`-escape ASCII letters** (`git`). `JSON.stringify` never does this.
- **NUL inside `git`.** Node refuses to spawn an argument containing NUL.
