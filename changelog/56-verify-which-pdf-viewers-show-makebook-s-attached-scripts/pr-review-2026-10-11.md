#### Important

**1. The prose under the table claims a negative that the table itself marks undetermined**

Location: `plugins/bookcraft/skills/makebook/SKILL.md:457` and `:468`, and
`plugins/bookcraft/skills/makebook/scripts/build-book.py:2963-2964`.

**What I see:**

```
**Of the six common viewers, only Firefox hands the reader the file.** ...
| Adobe Acrobat Reader 26.001 | not determined | refused: ... |
...
A reader in any other viewer has no way to get a script out of the PDF.
```

and in `attach_scripts`'s docstring: "of six checked only Firefox offers the file."

**The risk:** two lines above, the table says Acrobat Reader's attachments panel is "not
determined". "A reader in any other viewer has no way to get a script out" asserts that it
does not work, so the section contradicts its own table. "Any other viewer" also reaches past
the six that were checked, to every viewer nobody tried. The acceptance bar is that the section
agrees with the recorded results, and this one sentence does not. The practical effect leans the
safe way: a maker who believes it hands the scripts out anyway. The cost falls later. Whoever
picks up the deferred work, or re-measures, reads "no way" as settled for Acrobat when it was
deliberately left open. This does not block: `main` said "Not checked", and the branch is far
more accurate overall. It is a one-clause fix.

**Suggested fix:**

```markdown
**Of the six common viewers, only Firefox was seen to hand the reader the file.** ...

A reader in Preview, Safari, Chrome or Edge has no way to get a script out of the PDF, and
Acrobat Reader refuses the double-click; its attachments panel was not checked. The note names
Firefox for that reason. When readers may not use it, hand the scripts out beside the book as
well.
```

In the docstring, drop the result and leave the pointer, so a re-measure updates one place:

```python
    routes, because viewers support one, the other, both or neither. Which of
    the common ones does what is not measured here; SKILL.md records it.
```

**Learning note:** a results section should not claim more than its least-certain cell. When a
measurement was deliberately skipped, say so in the prose as well as the table. Readers take
the summary sentence and skip the grid. A measured fact kept in two places, here SKILL.md and a
docstring, will drift the first time one of them is re-measured.

#### Suggestions

**1. "Hand the scripts out beside the book" names no way to get them**

Location: `plugins/bookcraft/skills/makebook/SKILL.md:468`.

**What I see:** "When readers may not use it, hand the scripts out beside the book as well." The
binder writes no script files anywhere, so a maker following this has to work out where to get
them.

**Suggested fix:** one clause, verified on this branch's bind:

```markdown
... hand the scripts out beside the book as well: `pdfdetach -saveall -o <folder> <book>.pdf`
writes each one once.
```

Keep it to that clause. Having makebook write the files itself is the new work already under
`PLAN.md § Deferred`, and it does not belong on this branch.

**Learning note:** advice that tells someone to do something should come with the first concrete
step, or the reader stops at it.
