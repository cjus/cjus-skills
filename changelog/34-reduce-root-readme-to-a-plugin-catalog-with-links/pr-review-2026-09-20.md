#### Suggestions

🟢 **The catalog's closing line promises more than three of the four READMEs deliver**

📍 Location: `README.md:34`

**What I see:**

```markdown
Each plugin's own README is its full documentation: every skill it ships, what it costs to run,
how to configure it, and the one-time setup where there is any.
```

**The risk:**

"where there is any" only qualifies the last clause, so the sentence reads as a promise that all
four READMEs cover cost and configuration. Only `council` has a `## What it costs`, and only `pr`
has a `## Configuration`; `explain` has neither and says outright there is no setup step
(`plugins/explain/README.md:30`). It is a small overstatement, but this branch exists because the
root README made claims that had drifted from what the plugins actually say, so the replacement
sentence is worth holding to the same bar.

**Suggested fix:**

```markdown
Each plugin's own README is its full documentation: every skill it ships, plus its cost,
configuration and one-time setup where it has any.
```

**Learning note:** a trailing qualifier binds to the clause it sits next to, not to the whole
list. When one hedge is meant to cover several items, move it to the front or restructure, or a
reader will hold you to the unhedged reading.

🟢 **`under 250 words` is a tighter bound than the skill's own**

📍 Location: `README.md:31`

**What I see:** `as prose under 250 words`

**The risk:** `/explain:qe`'s bar is "at most 250 words" (`plugins/explain/README.md:5`), which
admits exactly 250. A 250-word answer satisfies the skill and contradicts the catalog. This is a
nit and fine to drop; I raise it only because the catalog row is now the only description of
`qe` a root-README reader sees.

**Suggested fix:** `as prose in 250 words or fewer` — matches the skill and reads no longer.

**Learning note:** "under N" and "at most N" differ by exactly one case, and summary prose is
where that distinction usually gets lost.
