re-running `--numstat`, because the 11/1699 totals validate cleanly and lend it credibility.

than a ratio and is exactly what `--numstat` already gives you.

### Important

🟡 **The detection fallback still tells the model "assume Claude-only", contradicting the
bullet `1555e05` rewrote to fix exactly that** — `plugins/council/skills/ask/SKILL.md:16`
(vs. `:25-29`).

The `!`-block read
`… || echo "detection unavailable — assume Claude-only"`, ten lines above a bullet telling
the model to seat OpenRouter anyway. Because `detect.sh` is phase 3, that fallback fires on
**every** invocation for the life of the branch, so the model met an imperative injected at
the top of its context and a contradicting instruction ten lines down — with position on the
imperative's side. A user with a valid key and three consented models would get a Claude-only
council and a footer saying so. `skills/setup/SKILL.md:11` already had the correct plain
form. Fix: strip the verdict from the data block and let the bullet interpret.

> **Resolved in `1ba65c5`.** `ask:16` is now
> `!`sh "${CLAUDE_PLUGIN_ROOT}/scripts/detect.sh" 2>/dev/null || echo "detection unavailable"``,
> matching `setup:11`. Re-verified in Part 1.

**Learning note:** a `!`-block is *data* the model reads, not a place to put instructions.
When a fallback string carries a conclusion it competes with the prose meant to draw it, and
prose ten lines down loses to context injected at the top.

---

🟡 **`Bash(git diff:*)` does not match the `git` invocation this skill instructs** —
`plugins/council/skills/ask/SKILL.md:5` (grant) vs. `:80` (instruction).

`1555e05` had narrowed `Bash(git:*)` to `Bash(git diff:*), Bash(git config:*)`, but the
instructed command is
`git -c core.fsmonitor= -c core.hooksPath=/dev/null diff --no-ext-diff --no-textconv <ref>`,
which starts `git -c …`. Permission patterns match literal command prefixes, so the grant
matched nothing and every attachment-by-diff would prompt on a path the frontmatter claimed
to cover. It fails closed, but a grant that looks right and matches nothing is worse than an
absent one. This branch's own `PLAN.md` relies on the same rule for the `M=`/`P=` item.

> **Resolved in `1ba65c5`** by taking option A: `Bash(git:*)` restored, matching
> `plugins/pr/skills/cp/SKILL.md:4`. **This is deliberate and must not be re-narrowed** — no
> `Bash(git diff:*)` form can match a command beginning `git -c`. Re-verified in Part 1.

**Learning note:** narrowing a permission grant is only a win if the narrow form still
matches. The test is mechanical: take the command the skill literally instructs and check
the grant is a prefix of that exact string, flags and all. Anything between the binary and
the subcommand — `-c`, `env VAR=…`, a leading assignment — breaks the match.
