### Summary

The branch keeps copied underscores inline by rounding every code font size to a quarter pixel, attaches each block the book asks the reader to save to the PDF as an embedded file, and warns about any save it cannot cover. `318ca15` makes an indented code block attachable, reads a save's direction from its own sentence rather than the whole paragraph, and raises the Playwright floor to the first release whose Chromium parses CSS `round()`. All three prior findings are fixed. The direction change also introduced one new mis-attachment shape, and a second, related shape has been there since the first commit.

### What is working well

- **The Critical is fixed in the general way, not just for the reported case.** `SCRIPT_PRE_RE` now captures the attributes of both tags, looks for the marker in either, and strips it from both. I checked shapes beyond the fixture: an indented block and a `file=` fence in the same chapter each get their own note, a raw `<pre>` HTML block ahead of a script does not pull the match off course, and a code body containing an escaped `</code></pre>` stays intact. None leaves a `data-script` behind. The only other literal `<pre><code>` matcher in the binder is the SVG figure rule (`build-book.py:1649`), and SVG fences are never marked as scripts, so the two cannot interact. The EPUB strip still works with the new capture group.
- **The fixture records why each case exists.** The `run.sh` header now says that markdown-it marks an indented block on `<pre>` and that missing it once failed the whole bind, so the next reader knows which case not to delete. `after.py` is now checked byte for byte, which is what makes the "Next, run it:" case bite.
- **The Playwright floor is right, and the upgrade path reaches it.** Playwright 1.44 bundles Chromium 125.0.6422.14, and 125 is the first Chromium with `round()`. `install.sh` runs `pip install -r` and then `python -m playwright install chromium`. A venv on 1.40 to 1.43 no longer satisfies the specifier, so the `install.sh` rerun that SKILL.md already asks for upgrades it and fetches the matching browser.
- **Docs moved with the code.** SKILL.md, the README fixture line, CHANGELOG.md and the (uncommitted) pr-summary edit all describe five scripts and the new direction rule.

**Verified locally:** `plugins/bookcraft/scripts/test-fixtures.sh --strict` passes 18 of 18 on macOS in 27 seconds (venv: Playwright 1.62.0, pypdf 6.19.0).

#### Important

🟡 **With no direction word in the save sentence, the block below is taken, even after "The script above..." or when it is the command that runs the file**

📍 Location: `plugins/bookcraft/skills/makebook/scripts/build-book.py:1146-1152` (the direction block in `find_scripts`)

**What I see:**

```python
back, ahead = SAVE_BACK_RE.search(sentence), SAVE_AHEAD_RE.search(sentence)
if back and not ahead:
    order = [prev]
elif ahead and not back:
    order = [nxt]
else:
    order = [nxt, prev]
```

The direction now comes from the save sentence alone, with no fallback. When that sentence has no direction word, the block below always wins. I ran `find_scripts` on parsed tokens from both commits in a scratch harness:

Shape A, which `318ca15` broke:

````markdown
```python
def f():
    return 1
```

The script above is complete. Save it as `f.py`.

```bash
python f.py
```
````

- `f76045f`: `f.py` is the Python block (the paragraph said "above").
- `318ca15`: `f.py` is `python f.py`.

Shape B, present since `f76045f`: the same Python block, then `Save it as `f.py` and run it:`, then the same bash block. **Both commits** attach `python f.py` as `f.py`.

**The risk:**
The failure is silent. The bind prints `scripts: 1 attached to the PDF: f.py (p. N)` and no warning, so the author has nothing to look into. The note sits under the command and tells the reader to save the attachment instead of copying the page, and the attachment is the command, not the script. The Python block the reader was asked to save gets no note at all. "Save it as `x.py` and run it:" followed by the run command is ordinary guide-book phrasing, which is the kind of book this branch targets.

Shape A is a side effect of how the previous 🟡 was fixed. That review's suggested fix narrowed to the save sentence only when the sentence **named** a direction, and fell back to the paragraph otherwise. The commit kept the narrowing and dropped the fallback. Shape B is new in this review, but it is in logic this PR authored, so it is in scope.

**Why this is 🟡 and not 🔴, and why it does not block:** the first review graded the same class of silent mis-attachment as Important, and I hold to that grading. The detector is documented as a heuristic, with `file=` as the exact override, and the bind names each attached script's page. It is not a regression against `main`, which attaches and warns about nothing for these shapes. It is still a gap in objective items 2 and 3 for a common phrasing, and the prototype below costs about ten lines, so **I recommend applying it before close.** The first guide book is due to be handed out the week of October 5.

**Suggested fix:**
Restore the paragraph fallback. When no direction is found anywhere, do not hand a named non-shell file a shell block:

```python
SHELL_LANGS = {"bash", "sh", "shell", "zsh", "console", "shell-session",
               "powershell", "ps1", "bat", "cmd"}
...
        # The sentence that asks for the save decides the direction; only when
        # it names none does the rest of the paragraph get a say.
        scope = sentence if (SAVE_BACK_RE.search(sentence)
                             or SAVE_AHEAD_RE.search(sentence)) else text
        back, ahead = SAVE_BACK_RE.search(scope), SAVE_AHEAD_RE.search(scope)
        if back and not ahead:
            order = [prev]
        elif ahead and not back:
            order = [nxt]
        else:
            # No direction anywhere: the shell block beside "Save it as `x.py`
            # and run it:" is how the file is run, not what it holds.
            hint = next((v for v in m.groupdict().values() if v), "")
            order = [b for b in (nxt, prev) if not (
                b and b[0] == "code" and hint
                and not hint.endswith((".sh", ".bash", ".zsh"))
                and (b[1].info.split() or [""])[0].lower() in SHELL_LANGS)]
```

I ran this against a scratch copy. Shapes A and B attach the Python block. Eight other shapes come out exactly as at `318ca15`:

- the first review's "Next, run it:" case;
- "below" in the save sentence with "above" in another;
- an indented block beside a `file=` fence;
- "Copy the code above into a file named";
- a save sentence ahead of the block;
- a nameless "Save this script so you can run it:" above a bash block, which still gets the "names no file" gap;
- "Save the lines below as `run.sh`";
- "Save it as `run.sh` and run it:", where the bash block is still taken.

`find_scripts` returns identical scripts and gaps for both `save-scripts` chapters. **Not verified:** the full suite with the patch applied in-tree.

An alternative that is never silently wrong: when the sentence gives no direction and **both** neighbours are code, report a gap ("say above or below, or put `file=` on the fence") instead of guessing. It trades a warning for a guess. I have not checked it against the fixture.

Either way, add shapes A and B to `save-02-where-the-binder-warns.md` and their expected contents to `want` in `run.sh`. Add one clause to SKILL.md's "In the sentence next to the block" bullet for whichever rule you pick.

**Learning note:**
When narrowing the evidence a heuristic reads, keep the wider evidence as the fallback instead of discarding it. The test added for the old bug proves the new case works. It says nothing about the cases the old code already got right, and shape A was one of those. Before changing a heuristic, pin a couple of the cases it currently gets right as fixture entries. This is characterisation testing, and it would have caught this.
