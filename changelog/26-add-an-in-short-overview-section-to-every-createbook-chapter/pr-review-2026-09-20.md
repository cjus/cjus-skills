# PR review: add an `## In short` overview section to every createbook chapter

Reviewed: `feature/26-add-an-in-short-overview-section-to-every-createbook-chapter`, 2 commits
ahead of `main` (`847be04`, `ed4653e`). No prior `pr-review-*.md` exists in this plan folder, so
this is a first review, not a delta review.

## Summary

The branch specs an `## In short` section in `reference/chapter-prose.md`, threads it through
`SKILL.md` (file format, step 4 `book.json`, step 5 prompt, a new step 6 pass, step 7 checker
description), and teaches `check-book.sh` eight things: four exemptions, a position rule, the cap
of three on the carried-in line, a glossary cross-check, and a word count on the summary line. A
new `fixtures/overview/` control fixture exercises all of it, `NOTES.md` records the decisions and
their losing alternatives, and bookcraft goes `1.0.2` -> `1.1.0`. The second commit stops the
script on a jq that is present but cannot execute.

The design work here is unusually good. The one blocking finding is a shell defect, not a design
one: the cross-check loop expands an array that is legally empty, under `set -u`, on the bash the
shebang actually resolves to on this machine.

## What is working well

- **Every new check actually fires.** I built six adversarial fixtures against
  `fixtures/overview/` and each rule produced the right failure: the cap on a four-term line that
  wraps, a term taught in the same chapter, a term absent from the glossary, a `Carried in:` line
  with no bold, a section that is not the first H2, and a missing section under `overview: true`.
  No rule was dead code, and none of them exited early and masked the others.
- **The wrapping bug was found and fixed before review.** Reading the carried-in line as a
  paragraph rather than a physical line (`check-book.sh:630-635`) is exactly right, and it is the
  difference between the cap being enforced and the cap being decorative. The fixture's
  carried-in line wraps deliberately, which is what made the bug findable. That is a fixture doing
  its job.
- **Counting bold spans rather than `(ch. N)` references** closes the hole where one malformed
  entry evades both the cap and the lookup at once. The reasoning is written down at
  `check-book.sh:637-639` and in `NOTES.md`, so the next person cannot undo it by accident.
- **The lookup matches whole keys, not substrings** (`check-book.sh:842`), with the `star schema`
  / `binary star schema` case named in the comment. Both sides lowercase (`tolower(term)` in the
  glossary awk, `tr` on the record), so the spec's own `**Grain**` at sentence start resolves
  against a `**grain**` entry. That was easy to get wrong and it is right.
- **The opt-in gate holds for the ordinary case.** I ran `main`'s checker and this branch's against
  the same pre-`overview` book: the output is byte-identical except for the new `overview: 0 (off)`
  field on the summary line.
- **The jq guard is the right shape.** `command -v jq && ! printf '{}' | jq -e .` distinguishes
  "absent, a supported configuration" from "present and broken, which silently downgrades every
  declaration", exits 2 rather than 1, and names the offending path in the message so the broken
  install is findable. Verified against the stale x86_64 jq on this machine.
- **`NOTES.md` records the losing alternatives, not just the winners.** The prefix-versus-inference
  decision and the checked-cap-versus-unchecked-walk asymmetry are both written down with the
  reason the asymmetry is principled, which is what stops it being revisited as an inconsistency.

## Issues found

### Critical

🔴 **The glossary cross-check aborts the whole run when no chapter carries a term in**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-book.sh:830`
(declared at `:216`)

**What I see:**

```bash
carried_records=()
...
if [ "$ovw_mode" = required ] && [ "$declared_gloss" = "true" ] && [ -f "$gloss_file" ]; then
  for rec in "${carried_records[@]}"; do
```

The script runs under `set -uo pipefail` (`:20`) with `#!/usr/bin/env bash` (`:1`). On this
machine that resolves to `/bin/bash`, which is 3.2.57. In bash before 4.4, expanding an **empty**
array as `"${arr[@]}"` under `set -u` is an unbound-variable error, not an empty expansion.

**Reproduced.** A one-chapter book built from `fixtures/overview/`'s chapter 1 (which correctly
carries no carried-in line, since chapter 1 never does) with `overview: true` and
`glossary: true`, and otherwise structurally sound:

```
check-book.sh: line 849: carried_records[@]: unbound variable
rc=1
```

**The risk:**

The script dies mid-run. It never prints the summary line, never runs the tag-mode reconciliation,
never runs the `content-checked` versus `chapters` reconciliation at `:906`, and never prints `OK`
or the final verdict. It exits 1, which a caller reads as "this book has failures" while the real
message is "this book was never finished being checked" — the exact confusion the script's own
header comment says it exists to prevent ("A checker that can report OK without having run is
worse than no checker", `:54-60`).

The trigger is not exotic. `carried_records` is empty whenever no chapter in the book names a
carried-in term, and the spec you wrote says that is normal: *"Zero is legal and common"*
(`chapter-prose.md § In short`), *"Chapter 1 always has none"*. So this fires on a single-chapter
book, on a book drafted chapter by chapter before the step 6 pass has added the carried-in lines,
and on any short book where every chapter happens to carry nothing in. It is also precisely the
state a book is in at the moment step 6 runs the checker for the first time.

**Suggested fix:**

Use the idiom this script already uses eleven lines further down, at `:909`, for exactly this
reason:

```bash
  for rec in ${carried_records[@]+"${carried_records[@]}"}; do
```

Or guard the block:

```bash
if [ "$ovw_mode" = required ] && [ "$declared_gloss" = "true" ] && [ -f "$gloss_file" ] \
   && [ "${#carried_records[@]}" -gt 0 ]; then
```

Either works; the first matches the existing convention in the file. Please also add the empty
case to `fixtures/overview/` or to a second fixture folder, because the current fixture's chapter
2 always populates the array, which is why this passed the fixture run.

**Learning note:**

`${#arr[@]}` is safe on an empty array in every bash; `"${arr[@]}"` is not, before 4.4. Since
`#!/usr/bin/env bash` on macOS resolves to 3.2 unless the user has a newer bash earlier on PATH,
any script that pairs `set -u` with arrays has to assume 3.2. The broader principle: the code path
your fixture does not reach is the one that ships broken, and "the array is empty" is a path
fixtures skip by default because fixtures are written to be interesting.

### Important

🟡 **A pre-existing book that uses `## In short` as an ordinary part heading now fails**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-book.sh:305-310`, `:599-656`,
`:684`

**What I see:**

`ovw_present` is set from the heading's presence alone, never from `ovw_mode`. Everything
downstream keys off presence: the position rule, the header-table rule, the cap, and the part
count at `:684` (`h2=$((h2 - sugg_present - ovw_present))`). `ovw_mode` gates only the *absence*
check at `:656` and the glossary cross-check at `:829`.

**Reproduced.** Taking `fixtures/fence/` (no `overview` key in its `book.json`) and renaming one
part heading to `## In short`:

```
main:   OK    structure is sound; read the seams for continuity
branch: FAIL  ...: "## In short" is not the first section; "## What the control holds constant" comes before it
        FAIL  ...: "## In short" does not follow the chapter header table; found: <!-- src: scripts/check-bo
        FAIL  ...: body has 1 part headings; a chapter's shape is two or three parts
```

**The risk:**

This contradicts two things the branch itself commits to. `PLAN.md` § Overview: *"The key is
absent by default so books written before this still pass."* And `SKILL.md` step 7, as this PR
rewrites it: *"**Where it declares `overview`**, it checks that each chapter carries `## In
short`, that it is the first H2 in the body with the header table immediately before it, and that
a carried-in line names at most three terms."* The code checks those three things whether the book
declares `overview` or not, so the documentation and the behaviour disagree, and a book that never
opted in can be failed by the opt-in feature.

I want to be fair about the precedent: `sugg_present` at `:661` works the same way, and following
the neighbouring convention is usually the right call. The difference is that `## Suggested
reading` has been a reserved section name since the format existed, whereas `## In short` is being
reserved *now*, against books already written. "In short" is a plausible thing for an existing
chapter to have called a part.

**Suggested fix:**

Gate presence on the declaration, so the whole downstream chain moves together:

```bash
  ovw_present=0
  ovw_start=0
  ovw_end=0
  if [ "$ovw_mode" = required ] \
     && printf '%s\n' "$body" | grep -qE "^[[:space:]]*${ovw_heading}[[:space:]]*\$"; then
```

with `ovw_mode` still driving the `elif` at `:656` for the missing-section case. A book that
declares `overview` is held to every rule; a book that does not is left exactly as `main` left it,
which is what the PR promises.

If you would rather keep presence-based checking deliberately, that is defensible — but then say
so in `SKILL.md` step 7 and in the `overview` key's paragraph at `SKILL.md:258`, because right now
both read as gated.

**Learning note:**

When a feature is sold as opt-in, the opt-out path is a contract, and the cheapest way to hold
yourself to it is to make the flag gate the *detection*, not just the *enforcement*. A flag that
only suppresses error messages still leaves the analysis running, and analysis has side effects —
here, the part count.

🟡 **When nothing marks the section's end, the entire chapter is silently counted as overview**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-book.sh:311-325`, `:897-902`

**What I see:**

The end-finder returns `0` when it reaches EOF without finding an H2, a paragraph tag, or a
provenance mark:

```awk
END { if (!found) print 0 }
```

and all three sweeps read `0` as "no end", i.e. run to EOF:

```awk
ovws && NR >= ovws && (ovwe == 0 || NR < ovwe) { ... }
```

The disclosure note is guarded twice: `ovw_fallback` is only incremented when
`[ "$ovw_end" -gt 0 ]` (`:323`), so the `ovw_end == 0` case never increments it at all, and the
note at `:897` additionally requires `prov_mode = required`.

**Reproduced.** A chapter with `## In short`, no part headings, no `## Suggested reading`, no tags
and no marks, in a book declaring `overview: true`:

```
chapters: 1  content-checked: 1  tagged: 0/1 (inferred)  prose: 0  structure: 29  overview: 79 (required) ...
chapter prose: mean 0    longest 0 in probe-01-no-tags-no-marks.md
OK    structure is sound; read the seams for continuity
```

Every word of the chapter landed in the overview figure. `prose: 0` and `longest 0` are both
wrong, and the whole body was exempted from the tag and provenance sweeps.

**The risk:**

Bounded, and I want to be precise about the bound. I checked the sharper versions and they are
still caught: a `tags: true` book whose only chapter is swallowed still fails on *"this book is
expected to carry paragraph tags and no chapter does"*, and a two-chapter book with one swallowed
still fails on *"1 of 2 chapters carry no paragraph tags while 1 do"*. So this is not a false pass
on a rule. What it is is a false *report*: `prose` and `longest chapter` are the two numbers the
script exists to hand a human ("the numbers are there for a human to notice a book turning into a
briefing, or one chapter the outline drew too wide"), and in this state they read 0. And unlike
the part-heading fallback — which you correctly disclose with a note — this one is silent, which
runs against the script's own closing principle at `:914`: *"A checker's silence about a file it
never opened reads exactly like a pass."*

**Suggested fix:**

Treat "found nothing" as the fourth rung of the fallback ladder and disclose it, rather than
letting it fall off the end. Minimally:

```bash
    if [ "$ovw_end" -eq 0 ] || printf '%s\n' "$body" | sed -n "${ovw_end}p" | grep -qE '^[[:space:]]*## '; then
      ovw_fallback=$((ovw_fallback + 1))
    fi
```

and drop `&& [ "$prov_mode" = required ]` from `:897`, widening the note's wording so it covers
both cases — the part-heading rung costs an unchecked mark, and the EOF rung costs the whole
chapter's prose figure. Both are worth a line of output whether or not the book carries
provenance.

**Learning note:**

A fallback chain wants a defined terminal rung. `print 0` here means "I failed", but the
consumers read it as "no limit", and that inversion is how a failure becomes a permissive default.
Where a sentinel and a legitimate value share an encoding, the consumer eventually picks the wrong
reading — prefer a distinct signal (`-1`, or a separate `found` flag) over overloading `0`.

### Suggestions

🟢 **The prefix constant drops the trailing space the spec fixes**

📍 Location: `check-book.sh:96`

`ovw_carried_prefix="Carried in:"`, but `chapter-prose.md § In short` and `PLAN.md § Settled
rules` both fix the literal as `Carried in: ` with the space: *"it opens with the literal
`Carried in: `"*. As written, `Carried in:**star schema** (ch. 11)...` parses as a carried-in
line. One character closes the gap, and the gap is only worth closing because the whole point of
the prefix rule is *"a parse that cannot drift"*.

🟢 **A second `## In short` in one chapter is counted as a part**

📍 Location: `check-book.sh:309-310`, `:684`

`ovw_start` takes `head -n 1`, and `:684` subtracts `ovw_present` (which is 0 or 1), so a chapter
carrying the heading twice has the second occurrence scored as a part heading. The position rule
still passes, since the first H2 is correct. Cheap to catch: count the matches and fail above one,
the way a duplicated glossary term already fails.

🟢 **The cross-check spawns one awk per carried term**

📍 Location: `check-book.sh:842`

`hit_ch=$(printf '%s' "$gloss_map" | awk ...)` runs inside the record loop, so an eighteen-chapter
book with three terms each is ~54 awk processes. It is not a problem at book scale and I would not
hold the PR for it, but a single awk pass reading `gloss_map` and all records at once would be one
process and roughly the same number of lines. Worth it only if you touch this block again.

🟢 **The joined carried-in paragraph preserves leading whitespace**

📍 Location: `check-book.sh:630-635`

`printf "%s ", $0` keeps each line's indentation, so a bold span wrapping onto an indented
continuation line yields a key with doubled spaces and a spurious *"which glossary.md does not
define"*. The glossary side normalises differently (`gsub(/\n/, " ", entry)` on an `RS=""`
paragraph). Adding `sub(/^[[:space:]]+/, "")` before the `printf` makes the two sides agree. The
failure mode is a false FAIL rather than a false pass, and the repo's markdown is not indented, so
this is genuinely optional.

  Occasion: next `check-book.sh` change. theme: fixture health.

   choice.
