## Summary

This is the mechanical substrate for the council port, landed ahead of any skill that
calls it: a self-contained `.env` reader with a three-level key precedence chain, the same
chain re-implemented in POSIX `sh` for Node-free callers, a dual-backend (jq or Node)
roster reader, the seating join, and 127 test cases across two oracle-table suites.

Scope was checked before any finding was written. Every file under review is **new**, so
nothing here can fail the in-scope test — there is no default-branch behaviour to have
regressed. The three skill directories, `reference/`, the marketplace entry, `detect.sh`
and `openrouter.mjs` are deliberately absent per the plan's status section and are **not**
treated as findings. The `## Deferred` block already in `PLAN.md` is treated as settled
and is not re-raised; one finding below is noted as extending one of those entries into a
failure class that entry did not name.

## What is working well

- **The two-implementations-one-oracle discipline is the right call and is genuinely
  implemented**, not just asserted. `oracle()` failing a row when the two sides *agree on
  a wrong answer* is the part most people leave out, and the `K=  # note` case in the
  comment proves it earned its keep.
- **The `#`-comment divergence from dotenv is correct and for the stated reason.**
  Truncating a credential into a 401 that points nowhere near the file is exactly the
  failure worth designing away, and both halves of the rule are pinned by tests.
- **"Failed to parse" and "no external members" are held apart everywhere it matters.**
  The refusal path is the default, the die messages say *why* refusal is happening, and
  `RC=$?` is captured before anything else runs — with the comment explaining that `if !`
  would have flattened the 3 into the wrong branch. That is a subtle POSIX trap sidestepped
  deliberately.
- **Secret hygiene is better than the bar.** No flag prints the value, the `set +x` /
  restore dance around the env read is the right shape, `-K -` keeps userinfo out of argv,
  and the `mktemp -d` scratch files carry roster data only.
- **The comments explain decisions, not mechanics.** `roster-rows.mjs`'s "why there are two
  backends" and `council-lib.sh`'s "two is already the maximum tolerable" are the kind of
  note that survives a year.
- File modes match the repo's existing convention exactly: `.mjs` at 644 with a shebang
  (as `pr-lifecycle-state.mjs`), `.sh` entry points at 755, the sourced library at 644.

### Important

🟡 **An empty middle field collapses in the `IFS=<tab> read` loops and shifts the whole seating row**

📍 Location: `plugins/council/scripts/council-state.sh:107`, `:114`, `:146`, `:244`, `:251`

**What I see:**

```sh
members claude | while IFS="$(printf '\t')" read -r stance model; do
  [ -n "${stance:-}" ] && seat "$stance" claude "$model" anthropic
done
```

**The risk:**

Tab is an **IFS whitespace** character. POSIX `read` strips leading and trailing runs of
IFS whitespace and collapses interior runs, so a row with an empty middle field does not
produce an empty variable — it shifts every field left by one. The TSV contract emits `-`
for a *missing* `stance`, but an *empty-string* `stance` passes through as `""`, producing
`member<TAB>claude<TAB><TAB>opus`.

Reproduced on both `/bin/sh` and `dash` with the roster
`{"members":[{"model":"opus","stance":""},{"model":"sonnet","stance":"b"}]}`:

```
  opus               claude      anthropic          <- text output
  {"stance":"opus","kind":"claude","model":"","vendor":"anthropic"}   <- --json
```

The model name has been promoted into the stance column, the model is empty, and in the
text renderer the vendor string lands in the model column (it shifts a second time on
read-back). Nothing warns. This is precisely the outcome the file exists to prevent: a
confident seating row the script has not established. The same shift is reachable through
an empty `openrouter`/`ollama` `stance`, and a member with *both* fields empty is silently
dropped by the `[ -n "${stance:-}" ]` guard, under-counting the council.

The oracle suite cannot see it because no fixture contains an empty string — `R_ODDMEMBER`
covers *missing* keys and non-object entries, which the `// "-"` / `?? "-"` defaults
already handle.

**Suggested fix:**

Fix it at the contract boundary rather than at every reader, so both backends and all four
loops are covered at once. Normalize empty to the same `-` sentinel that missing already
uses:

```jq
# council-lib.sh, in COUNCIL_ROSTER_JQ
+ [ (.members // [])[] | select(type == "object")
    | "member\tclaude\t\(.stance | if . == null or . == "" then "-" else . end)\t\(.model | if . == null or . == "" then "-" else . end)" ]
```

```js
// roster-rows.mjs
const cell = (v) => (v === undefined || v === null || v === "" ? "-" : String(v));
out.push(`member\t${kind}\t${cell(m.stance)}\t${cell(m[idField])}`);
```

Then add an `empty-strings` fixture to the Part 3 parity list and one Part 2 row asserting
`.seated[0].model` is not the vendor. If you would rather keep empty strings distinguishable
from missing ones, the alternative is to switch the delimiter to a non-IFS-whitespace
character such as `\037` (unit separator), which has the side benefit of retiring the
TSV-injection entry already in `## Deferred`.

**Learning note:**

`IFS=$'\t' read` looks like it gives you strict field semantics, but IFS splitting has two
classes: whitespace characters (space, tab, newline) coalesce and are stripped at the ends;
every other character is a hard delimiter that produces empty fields. Setting IFS to a tab
therefore does *not* get you `cut -f` behaviour. Any time a shell reads a delimited record
and the delimiter is a whitespace character, empty fields are lost — and the loss is a
silent shift, not an error.

🟡 **Three `--json` fields are interpolated without escaping while their siblings are escaped**

📍 Location: `plugins/council/scripts/council-state.sh:215-223`

**What I see:**

`rows()` correctly escapes every string it emits, and the comment above it states the
invariant plainly — *"Every string here comes from the roster, which is user-authored, so
it is outside this program and must be escaped."* Three fields in the surrounding `printf`
calls skip it:

```sh
printf '{"key":{"present":%s,"source":%s},"roster":{"path":"%s","state":"%s"},' \
  ... "$COUNCIL_KEY_SOURCE" ... "$ROSTER_DISPLAY" "$ROSTER_STATE"
printf '"projectedCorrelation":"%s","vendors":"%s",...' "$CLASS" "$VENDORS" ...
```

**The risk:**

`vendors` is roster-derived — it is `${id%%/*}` over the seated models — so it is squarely
inside the invariant the comment states. Reproduced with a model id of `ac"me/x`:

```
..."vendor":"ac\"me"}],...,"vendors":"ac"me",...
==> INVALID JSON (jq refuses to parse the tool's own output)
```

`roster.path` and `key.source` are path-derived (`$COUNCIL_ROSTER`, `$PWD`,
`$XDG_CONFIG_HOME`), and a directory containing a `"` or `\` is legal on both platforms —
also reproduced. The consequence is the one the file's own comment names: the consumer's
parse fails, a parse failure at that layer reads as "no seating information", and you land
back on a confidently-wrong seating table. `esc()` also does not cover the other JSON
control characters (`U+0000`–`U+001F` minus the three it handles), which a `"stance":
"ab"` would hit.

**Suggested fix:**

Hoist the escaping out of the `awk` and make it apply to every string that reaches the JSON
writer:

```sh
jesc() { # any string -> JSON-string body
  printf '%s' "$1" | awk '{ gsub(/\\/,"\\\\"); gsub(/"/,"\\\""); printf "%s", $0 }'
}
```

then wrap `$VENDORS`, `$ROSTER_DISPLAY` and `$COUNCIL_KEY_SOURCE` at their three use sites.
For the control-character gap, add a loop in `esc()` over `\001`–`\037` emitting `\uXXXX`.
A parity row asserting `jq -e . <<<"$out"` succeeds for a hostile *vendor slug* — the
existing hostile fixture only exercises a *stance* — would have caught this.

**Learning note:**

When a program hand-writes JSON, the escaping has to live at the writer, not at the call
site. Escaping applied per-field is escaping that will be forgotten the next time a field
is added — which is exactly what happened here between the prior review's fix and this one.

🟡 **The two roster backends disagree at the refusal boundary: jq refuses an ill-typed container, Node reports confident seating**

📍 Location: `plugins/council/scripts/roster-rows.mjs:53-74` vs `council-lib.sh:238-251`

**What I see:**

Node coerces every container it does not like into an empty one:

```js
const ext = roster.external ?? {};     // "nope" stays "nope", then ext.openrouter -> undefined -> {}
for (const m of Array.isArray(list) ? list : []) { ... }
```

jq, given the same input, errors on the first index or iteration and the caller maps that
to `return 2` — refuse.

**The risk:**

Which backend runs depends on what happens to be installed, and `council_json_backend`
prefers jq, so the *permissive* path is the one a Claude-only machine with no jq falls onto
— the exact user this dual-backend design was built to protect. Measured:

| roster | jq | node |
|---|---|---|
| `"external": "nope"` with 1 claude member | refuses, rc=2 | `1 seated, HOMOGENEOUS`, rc=0 — the whole `external` block silently vanishes |
| `"members": {"a": {...}, "b": {...}}` (object map) | `2 seated, HOMOGENEOUS` | `0 seated, NONE` |
| `"models": {"x": {...}}`, enabled | member listed under `notSeated` | member absent entirely |
| `"external": {"openrouter": "yes"}` | refuses, rc=2 | `0 seated`, rc=0 |

Row 2 is the worst shape: **both** backends answer confidently and they disagree about how
many members the council has. Row 1 is the forbidden outcome stated in `council-state.sh`'s
own header — a roster the user believes is in effect reported as a Claude-only council.

Scope note: `## Deferred` already carries a **"Roster-shape backend parity"** entry, but it
describes *scalar rendering* divergence (`false` under `//` vs `??`, an array joined with a
comma) with the occasion *"next time the roster schema gains a field."* This is a different
class — a refuse-versus-report flip on container typing, reachable today without any schema
change — so I am raising it rather than treating it as settled. Triage may reasonably merge
the two under one theme.

**Suggested fix:**

Make Node as strict as jq, since refusing is the designed behaviour and the cheaper
direction to converge on:

```js
const obj = (v, what) => {
  if (v === undefined || v === null) return {};
  if (typeof v !== "object" || Array.isArray(v)) {
    process.stderr.write(`roster: ${what} is not an object\n`);
    process.exit(2);
  }
  return v;
};
const arr = (v, what) => {
  if (v === undefined || v === null) return [];
  if (!Array.isArray(v)) {
    process.stderr.write(`roster: ${what} is not an array\n`);
    process.exit(2);
  }
  return v;
};
const ext = obj(roster.external, "external");
const or  = obj(ext.openrouter, "external.openrouter");
// ... and arr(roster.members, "members"), arr(or.models, ...), arr(ol.models, ...)
```

Then extend the Part 3 `names` list with `bad-external`, `object-members` and
`object-models` fixtures, which is where this class belongs permanently.

**Learning note:**

When two implementations back one contract, the parity test has to cover the *refusal*
boundary as well as the success surface. Two engines that agree on every well-formed input
can still disagree completely on malformed input, and malformed input is where the
consequence lives — one engine says "I cannot tell you", the other says "everything is
fine". `??` and `//` are convenience defaults, and every convenience default is a place
where a type error becomes a silent zero.

### Suggestions

🟢 **`PROBE_SKIPPED` is set even when the roster declares no Ollama members**
📍 `council-state.sh:144`. With `"ollama": {"enabled": true, "models": []}` and an
OpenRouter member seated, the footer reads `CROSS-VENDOR (anthropic, deepseek) -- ollama
was not probed, so this diversity is unconfirmed` — but no Ollama member is seated, so the
diversity that *is* claimed is fully confirmed. It errs toward under-claiming, which is the
safe direction, so this is polish rather than a defect. Gate the flag on at least one
Ollama member actually reaching `seat`.

🟢 **`maxConcurrentExternal` is type-checked on the `--json` path only**
📍 `council-state.sh:214` vs `:263`. `{"maxConcurrentExternal": "two"}` yields `2` in JSON
and `concurrency: maxConcurrentExternal two` in text, from the same run. Move the
`case "$MAXCONC" in ''|*[!0-9]*) MAXCONC=2 ;; esac` up to line 105, next to the
`[ -n "$MAXCONC" ] || MAXCONC=2` it belongs with, so both renderers see one value.

🟢 **The two key-chain warnings never reach a `--json` consumer**
📍 `council-state.sh:229`, `:233`. `COUNCIL_KEY_MODE_WARN` (a world-readable key file) and
`COUNCIL_KEY_WARN` (a configured-but-failing `.env` level) print in `--text` and are dropped
in `--json`. Decision 3 has `/council:status` consuming this script, and a world-readable
credential is the one thing you do not want format-dependent. Add
`"warnings": [...]` to the JSON object before a caller exists that would need it added
compatibly.

🟢 **`COUNCIL_JSON_BACKEND` silently ignores an unrecognised value**
📍 `council-lib.sh:257-260`. `COUNCIL_JSON_BACKEND=python` falls through the `case` into
auto-detect and reports nothing. A `*) echo "unknown backend" >&2; return 1 ;;` arm would
make a typo in the suite fail loudly instead of quietly testing the default path twice.

## Verdict

VERDICT: APPROVE

Nothing blocks. The PR delivers the mechanical substrate it set out to deliver, all six
prior findings were verified fixed rather than assumed, and the plugin is inert on install.
The three 🟡 items are defects in new code and are worth closing before Phase 4 wires
`skills/ask` and `/council:status` to this script — at that point a shifted seating row or
an unparseable `--json` stops being a latent bug and starts being a wrong answer in
someone's context window.
