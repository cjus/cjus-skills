## Summary

This branch gives every `/createbook` book an `assertions.json` beside its `book.json`. It holds
what the book was told or settled that no source holds, written only through
`createbook/scripts/assertions.sh`, whose `problems_in` is the format's single definition.
`check-provenance.sh` resolves `assertion <id>` mark components against it, fails a citation of a
missing, superseded or retired entry, sweeps superseded premises' `search` phrases as REVIEW, and
reports uncited `expected` entries. `/createbook`, `/updatebook` and `/check-claims` stop and
backfill a book with no file, and `/createbook --recreate` carries the file into a new folder.

**Scope, as applied.** This is the first review on the branch; no earlier `pr-review-*.md`
exists. I reviewed this branch's own commits and not #45's, which arrived through the merge. Both
`## Decision` sections in `PLAN.md` (the recreate flag into a new folder, and backfill
confirmation by triage) are treated as settled. Phase 7, the backfill of the reference guide, is
not treated as missing work. The pr 0.2.7 change is operator-directed, so I checked it for
correctness only. The PLAN's own `## Deferred` entry, a review file for oversized backfills, is
not re-raised.

## What is working well

- **One definition of the format, and it really is one.** `check-provenance.sh` imports `load`
  through the same by-path loader it already used for `check-references.sh` and never parses the
  file itself. So the file cannot be read two ways, and a newer `format` produces the same
  `too_new` wording from both scripts.
- **The write path cannot leave a broken file.** `_read` refuses to layer a change onto a file
  that already fails, `_commit` refuses to write one that would fail, and `_write` goes through
  a temp file and `os.replace`. `dump` is faithful by construction, because only documents that
  passed `problems_in` reach it, and every allowed key appears in its orderings. The fixture
  proves a refused write leaves the file byte-identical.
- **`next_id` with no gaps below it** closes a hole that uniqueness alone leaves open: delete the
  newest entry and the next `add` would reuse its ID, so an old mark would resolve cleanly to a
  different claim. `deleted-entry.json` pins it. The repeated-JSON-key refusal via
  `object_pairs_hook` is the same kind of thinking: it catches the silent failure Python's parser
  would otherwise hide.
- **The three register states in the checker are the right shape.** A file that fails its own
  check fails the run and resolves nothing against it, so no verdict rests on a broken entry. A
  missing file prints `assertions NOT CHECKED` rather than letting a vacuous pass read as a real
  one.
- **`cited` is built from every chapter, never the scoped subset**, which mirrors the existing
  `defined` tag set. The comment explains the false report that `--chapters 3` would otherwise
  produce.
- **The sweep's text handling is careful.** Whitespace and emphasis between words, whole-word
  boundaries that exclude "twenty-first", and SVG markup blanked character for character so the
  reported line is the file's own line. The fixture proves the line-break-plus-bold case and the
  split-`<tspan>` case.
- **The fixture design is strong.** Rebuilding the committed file from the helper's own commands
  and requiring byte-identity pins the format, the key order and every command at once. The
  guard that fails any `malformed/*.json` that `run.sh` does not assert is a nice touch.
- **Docs and code agree** on nearly every rule. I walked each row of `§ The assertions file`'s
  block, kind and field tables against `problems_in`, and the exceptions are listed below.

#### Important

🟡 **1. The backfill's `supersede` step writes the new value as `expected`, and nothing can turn it back**

📍 Location: `plugins/bookcraft/skills/createbook/SKILL.md:762`;
`plugins/bookcraft/skills/createbook/scripts/assertions.sh:711-717` (`_finish`) and `:783-800`
(`cmd_supersede`)

**What I see:**
Step 6 of `§ Backfilling the assertions file` says:

> A premise that changed is added as the old value, then `supersede`d by the new one, each dated
> to its own commit, with the `search` phrases from step 3.

It gives no `--citation legacy`. `supersede` carries over the kind, `applies_to` and `reaches`,
but not `citation`, and `_finish` defaults a prose entry to `expected`.

**The risk:**
Every changed premise a backfill records comes out `expected` with no mark citing it. The
reference guide's twenty-to-eleven pair is exactly this case. From then on, `check-provenance.sh`
reports it as "no mark in the book cites it" on every run, which is the standing noise `legacy`
exists to prevent. The SKILL and README describe that report as "what the new book dropped". It
cannot be undone, either: `expect` only goes from `legacy` to `expected`, and skills never edit
the file by hand, so one missed flag leaves a permanent REVIEW line until a chapter rewrite cites
the entry. The fixture's own `build()` passes `--citation legacy` on its `supersede`
(`run.sh:67-69`), which shows the flag is needed. The procedure just does not say so at the line
where an agent will act.

**Suggested fix:**
The minimal fix is in the doc:

```markdown
- **A premise that changed is added as the old value, then `supersede`d by the new one with
  `--citation legacy`**, each dated to its own commit, with the `search` phrases from step 3.
```

and one sentence in the `supersede` docstring: "`citation` does not carry over; a backfill passes
`--citation legacy`." For the code-level alternative, see Question 2.

**Learning note:**
A default that is right for one caller (`/updatebook`, where the rewrite cites the new entry
straight away) and wrong for another (the backfill) has to be overridden at the exact line the
second caller reads. A general rule stated three paragraphs earlier is not enough.

🟡 **2. The entry checks and the premise sweep never run on a book without `"provenance": true` or a `sources` map**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-provenance.sh:1604-1614` (the two
early `return 0`s) against `:1671` (where the register is first read);
`plugins/bookcraft/skills/createbook/SKILL.md:768` (backfill step 7)

**What I see:**
Both early returns exit 0 before `assertions.json` is opened. The note they print says "this
book carries no marks to check. Nothing was asserted", and it says nothing about the entries or
the sweep.

**The risk:**
The backfill fires for any folder with a `book.json`. The SKILL says a book written before the
provenance format existed still passes without declaring it, and those older books are the ones
most likely to need a backfill. On such a book, backfill step 7 ("show every `REVIEW` line its
sweep prints") finds none, and an agent will report that nothing is still built on the old
premise. `/updatebook`'s "Changes a premise" row has the same blind spot. The sweep needs only
the file and the folder, and it depends on marks and sources only because of where it sits in
the script. The PLAN's "it never passes quietly" does not hold on these two paths.

**Suggested fix:**
Read the register and run `sweep()` ahead of both early returns, or at least on them, since the
sweep needs neither marks nor sources. For example, factor the register read into a helper and
call it on both paths:

```python
def assertions_only(book):
    """The checks that need no marks: validate the file and sweep superseded premises."""
    path = book / register.FILE
    if not path.exists():
        print(f"assertions NOT CHECKED: this book has no {register.FILE}")
        return
    doc, probs = register.load(path)          # TooNew handled as in main
    if doc is None or probs:
        for p in probs:
            problem(f"{register.FILE}: {p}")
        return
    reg = {e["id"]: e for e in doc["entries"]}
    swept, passages = sweep(book, reg)
    print(f"assertions {len(reg)} entries   superseded premises swept {swept}, "
          f"passages found {passages}   (no marks: uncited report not run)")
```

At the least, add one sentence to backfill step 7 saying that the sweep needs
`"provenance": true`, and that without it the agent greps the `search` phrases instead.

**Learning note:**
A check bolted onto the end of an existing pipeline inherits every early exit above it. When
its preconditions differ from the pipeline's, it belongs before those exits.

🟡 **3. In a supersession chain, "now:" names a value that is itself superseded**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-provenance.sh:1510` (in `sweep`)
and `:1791` (in the FAIL detail for a mark citing a superseded entry)

**What I see:**
`now = reg[e["superseded_by"]]` follows one hop. The `sweep` docstring says: "Each hit names
what the premise says now, since that is what the passage has to become."

**The risk:**
A premise that changes twice (twenty, then eleven, then twelve) is a normal flow through the
helper, because `supersede` accepts any entry that holds, including an earlier replacement. Hits
on the first value then read "now: The roster is eleven students", which is itself superseded.
The operator is sent to rewrite chapters to a stale value, and the next run flags them again
under the middle entry. A chapter rewrite is the expensive path
(`updatebook § When to stop editing in place`), so doing it twice costs real time.

**Suggested fix:**

```python
def current(reg, e):
    """The entry a supersession chain ends at: what the claim says now."""
    while e["status"] == "superseded":
        e = reg[e["superseded_by"]]   # check guarantees each hop is newer, so this ends
    return e
```

Use `current(reg, e)` at both sites. Where the end of the chain is `retired`, say so
("now: retired: <reason>") rather than quoting its statement. A three-link chain would be a
cheap case to add to the fixture.

**Learning note:**
A link field names the next hop. "What is true now" is the end of the chain, and code that
promises the second while reading the first is right only until the data has depth.

🟡 **4. No fixture covers the worklist's new `entries` and `settled`**

📍 Location: `plugins/bookcraft/skills/createbook/scripts/check-provenance.sh:1381-1389`,
`:1765-1790` and `:1985-1989`; `plugins/bookcraft/skills/createbook/fixtures/assertions/run.sh`

**What I see:**
`--emit-worklist` is how `/check-claims` agents receive their entries. That is a Phase 4
deliverable, and the new `judgement.md § Entries the book stands behind` depends on it. No
fixture runs `--emit-worklist` over a book that has an `assertions.json`. The appendix fixture's
book has none, so it only ever sees empty lists. The whole-book `cited` set under `--chapters`
is also unexercised, because the fixture has one chapter.

**The risk:**
If `settled` dropped out of the chapter file, or `entries` out of a unit, no test would fail. The
first sign would be `/check-claims` raising a settled finding again on the reference guide, which
is the regression the feature exists to prevent.

**Suggested fix:**
Add one block to `run.sh`. The fixture already has what it needs: units citing entries 2, 6 and
7, and entry 7 as the one settled entry that holds.

```bash
out=$("$scripts/check-provenance.sh" --emit-worklist "$tmp/wl" "$here" 2>&1); rc=$?
[ "$rc" -eq 0 ] && python3 - "$tmp/wl/assertions-fixture-01-entries-that-hold.json" <<'PY'
import json, sys
d = json.load(open(sys.argv[1]))
assert [e["id"] for e in d["settled"]] == [7], d["settled"]
assert d["settled"][0]["answers"][0]["was"] == "B", d["settled"]
cited = {e["id"] for u in d["units"] for e in u["entries"]}
assert {2, 6, 7} <= cited, cited
PY
report $? "check-provenance --emit-worklist: each unit carries its entries, the chapter file the settled one"
```

The `--chapters` case needs a second chapter, and can wait.

**Learning note:**
The fixture pins what the checker prints. The worklist is a second output with a different
consumer, so it needs its own assertion, or it is guarded only by the author's memory.

#### Suggestions

🟢 **1. Every write leaves `assertions.json` at mode 0600.** `tempfile.mkstemp` creates the temp
file as 0600, and `os.replace` keeps that mode. The fixture's own file on disk is `-rw-------`
for this reason. Git records `100644`, so clones are unaffected, but locally every write silently
resets a 0644 file to owner-only, and a process under another uid (a container, a shared
machine) then fails to read it with a traceback. Before the `os.replace` in
`assertions.sh:616-628`, apply the old file's mode, or 0666 masked by the umask for a new file:

```python
if path.exists():
    os.chmod(tmp, stat.S_IMODE(path.stat().st_mode))
else:
    um = os.umask(0); os.umask(um); os.chmod(tmp, 0o666 & ~um)
```

🟢 **2. `init --how createbook` could refuse a folder that already has `OUTLINE.md` or chapter
files.** The `created` rule exists to tell a real file from "one written to get past a presence
check". Nothing stops an agent facing a one-word-fix stop from running `init --how createbook`
on an old book, and the result passes `check` with no entries. Step 1 runs `init` before
`OUTLINE.md` exists, and neither the recreate nor the backfill uses this form, so the guard
blocks no legitimate path.

🟢 **3. "The OK line says so too" holds only for a clean OK.** `createbook/SKILL.md:595` says a
book with no file is flagged on the OK line as well. `check-provenance.sh` prints that sentence
only under `OK`, not under `OK*`. The `assertions NOT CHECKED` summary line is always present, so
either print the note under `OK*` too, or reword the doc to "a clean OK line".

🟢 **4. The SVG sweep does not decode XML entities.** A phrase containing an apostrophe won't
match a figure that spells it `&#8217;` or `&apos;`. Running `html.unescape` on the text after
the tags are blanked is safe for the line numbers the sweep reports, because no entity spans a
newline. This is low priority, and Phase 7 will show whether real figures use entities.

🟢 **5. Two small details.** `check-provenance.sh:1926` lost a space (`unreadable =[`).
`createbook/NOTES.md:1060` says `run.sh` runs the checker over "four mutated copies". It runs
five: superseded, retired, unreadable component, missing file and reserved name. Counting the
newer-format copy, it is six.

**Considered and dropped, not worth a ticket:**

- `correct`, run twice on one item, keeps only the latest `was`.
- A non-UTF-8 or unreadable `assertions.json` raises a traceback rather than printing a FAIL
  line.
- `check` does not require a replacement premise's `search` to differ from the old one's.
- A mark may cite a `book` entry (the fixture's `assertion 3 (the ruling)` does), although the
  helper's wording says no mark cites one.

Each is real, but arguable at this stage.

2. **On Important 1:** would you rather `supersede` carry `citation` over from the old entry when

   the agent forgets. The doc fix keeps today's stricter default, which is why I suggested it
   first.
