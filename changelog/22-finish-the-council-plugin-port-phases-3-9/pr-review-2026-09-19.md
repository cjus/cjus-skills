### What is working well

- **The seating join is now a single authority, and the tests prove it rather than assert it.**
  `test-council-state.sh` diffs `.seated[]` against `council_default_members` output directly, so
  a second copy of the default list fails the suite instead of drifting. The companion row that
  feeds every default pin through `council_pin_is_accepted` couples two independent declarations
  that nothing else couples. That is the right shape for this class of bug.
- **The `COLLAPSED` split is the honest answer to a question that could not be fully answered.**
  The mechanically checkable half (a pin outside the closed enum) moved into the join where it
  costs nothing; the unobservable half stayed as member self-report with full-collapse-only
  confirmation; and `reference/roster.md` records precisely what the probe did *not* establish.
  A lesser branch would have shipped a class that can never fire.
- **`openrouter.mjs`'s argument parsing refuses the traps instead of the typos.** Rejecting a
  value that begins with `--` stops `--model --prompt-file x` from billing a request for a model
  named `--prompt-file`, and exiting 5 on the retired `M=`/`P=` form with the replacement named is
  the difference between a migration and a mystery.
- **The fetch stub is the right call over an endpoint override.** An env var that redirects a
  bearer token is exactly the property the script exists to hold; `node --import` buys the same
  coverage with no production change, and the stub recording `argv` lets the suite assert both
  halves — the key *is* sent as a bearer token, and it never reaches argv.
- **`detect.sh` degrades where it must.** `set -u` plus `exit 0` on every reported path, a named
  cause when `council-lib.sh` is missing, `curl -K -` so basic-auth userinfo never enters the
  process table, and NOT PROBED kept distinct from not reachable.

#### Important

🟡 **`NONE` now says "the roster declares no members" for a roster that declares members and had
them all unseated**

📍 Location: `plugins/council/scripts/council-state.sh:214-215, 294`; the matching skill prose at
`plugins/council/skills/ask/SKILL.md:127-131`

**What I see:** the new pin check unseats a Claude member whose `model` is outside the enum. With
a roster whose Claude members all carry a typo'd pin, I ran:

```
$ COUNCIL_ROSTER=... sh council-state.sh --text --no-probe
not seated (consented in the roster, unavailable here):
  risk-first         claude      opus-4.5   (not a model this harness accepts (opus|sonnet|haiku|fable))
  contrarian         claude      sonnet-4   (not a model this harness accepts (opus|sonnet|haiku|fable))
projected correlation: NONE -- the roster declares no members
```

and `--json` gives `{"total":0,"class":"NONE","notSeated":["opus-4.5","sonnet-4"]}`.

`skills/ask` then reads that as: *"`.projectedCorrelation: "NONE"` with `.seating.total: 0` means
the roster is present and declares nobody. Say so, point at `/council:setup`... A roster
declaring no members is a decision."* The roster declared four members; the user made a typo.

**In-scope justification (Phase 2b, exception 1 — materially worsened).** A present roster
reaching `0 seated` was possible on `main` only through an external-only roster where nothing
resolved. This PR makes it reachable from the ordinary Claude-member path — a single typo'd pin
in the shape `/council:setup` writes — and the prose that interprets the class as "a decision you
made" is new in this PR (`git show main:...skills/ask/SKILL.md` has no `Zero seated` section).

**The risk:** this is the same self-contradiction Decision 1 was written to remove, reappearing
one row down. The report lists the members two lines above the claim that there are none, and the
skill is instructed to tell the user the roster declares nobody — which sends them to add members
they already have, rather than to fix a pin. `reference/roster.md:49-51` and
`plugins/council/README.md:145` carry the same reading.

**Suggested fix:** the smallest honest version is to distinguish the two zero-seated cases at the
point the class is chosen, since `$UNSEATED` already holds the evidence:

```sh
if [ "$N_SEATED" -eq 0 ]; then
  if [ -s "$UNSEATED" ]; then CLASS=NONE; NONE_REASON='every member the roster declares is unavailable here -- see "not seated" above'
  else                        CLASS=NONE; NONE_REASON='the roster declares no members'; fi
```

and print `$NONE_REASON` at line 294. If you would rather not widen the output contract this late,
the cheaper fix is prose only: soften the three docs to "no member was seated" and have
`skills/ask` branch on `.notSeated | length > 0` before telling the user the roster declares
nobody. Either way, add the all-pins-bad fixture to `test-council-state.sh` beside `R_BADPIN` —
the suite's existing rows cover one bad pin among two members, which is exactly the case that
hides this.

**Learning note:** a class computed from a count loses the reason behind the count. When two
different causes collapse into one output token, the message attached to that token can only be
true for one of them — which is the same argument the branch already made for `absent` versus
`present, no members`.

**What I see:** *"The probe cases belong to phase 8 and are deliberately not here yet; every row

above"*. In `skills/ask/SKILL.md` that was true — `detect.sh`'s `!` block is at the top. In the
extracted file it resolves to nothing.

**The risk:** the reader is a model that was sent here to learn how to call Ollama. A dangling

**Suggested fix:** name the source: *"the `ollama-endpoint:` line in `/council:ask`'s availability

for a credentialed endpoint — `detect.sh` prints it through `council_redact`, so the *exact*

#### ⏭️ Deferred to follow-up

- **A network failure in `openrouter.mjs` still exits 1 with an unhandled rejection**,
  `plugins/council/scripts/openrouter.mjs:138-146` — `await fetch` and `await response.json()` are
  uncaught, so a DNS failure, a refused connection or the 600s `AbortSignal.timeout` exits 1 with

  rule for it, so it is reported as an unclassified failure rather than a provider outage.
  *occasion:* next time `openrouter.mjs` is touched — the stub already has the shape to test it
  (`throw` from the stub, assert exit 4). theme: openrouter exit-code contract

  through `esc()`, but these two are interpolated raw, so a `"` or `\` in `$COUNCIL_ROSTER`
  produces invalid JSON. Pre-existing and untouched by this PR.
  *symptom:* a roster path containing a quote makes `--json` unparseable, which `skills/ask` would
  most likely handle as "no seating information".
  *occasion:* alongside #15's output-contract items, which already own this file.
  theme: council-state JSON escaping
- **`detect.sh`'s roster endpoint scrape takes the first `"endpoint"` in the file**,

  ticket; noting it only so the next reader does not re-derive it. theme: detect.sh roster scrape
- **The wrong-architecture `jq` item already recorded under PLAN's `## Deferred`** — carried
