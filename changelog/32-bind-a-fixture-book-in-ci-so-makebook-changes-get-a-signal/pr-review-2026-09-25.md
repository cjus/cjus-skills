# PR review: Bind a fixture book in CI so makebook changes get a signal

Review date: 2026-09-25, by `/pr:pre-test`, over `main...HEAD` at `8bb3b93` (PR #41). Changes that
arrived with the merge of `main` @ `5a4d741` (#39) were out of scope.

**Verdict: APPROVE.** No Critical issues and no regression against the objective. One Important
finding strengthens a new check and is worth doing before `/pr:close`; it does not block testing.

## Summary

The fixtures workflow installs the binder's toolchain and asserts that it runs: Chromium prints a
probe page and `pdftotext` reads it back. `makebook/fixtures/bind/run.sh`, run by
`test-fixtures.sh`, binds copies of the guide fixture twice and two regression books, and asserts
on what the binder writes.

## What is working well

- Exit codes are captured correctly: `bind()` declares `local rc` on its own line, so `rc=$?` is
  the bind's status. The page-2 check keeps `2>&1`, so a `pdftotext` error surfaces in the FAIL.
- The copies protect the tracked fixtures. A finished bind leaves its copy byte-identical, and
  `git status` is empty after a full run.
- The skip-versus-fail split is right: skip only when the venv or `pdftotext` is absent; a
  toolchain present but broken fails; `--strict` and `$CI` fail any skip.
- Every settled decision is implemented as decided: a `run.sh` in the suite, two binds (the PNG
  magic-byte check catches the swallowed rasterising failure; `cover.xhtml` is read only where
  `cover_image` keeps it), Linux advisory with its reason in the header, no cache, and the
  regression books one level below `fixtures/*/`, out of the coverage loop's reach.
- The stamp regex checks the whole form, not the word.
- The docs count is right ("Seven fixtures"), and no claim that the suite does not bind remains.

Checked by the reviewer: `/bin/bash` 3.2 parses `run.sh` and every workflow `run:` block; the full
fixture passes 11 of 11 locally in 9.5s; `check-citations.py` passes; the banned-terms and
attribution audit is clean across the tree, the commit messages and the added lines.

## Issues found

### Critical

None.

### Important

**1. The appendix-table check trusts the binder's own alarm, so it can pass vacuously.**
`plugins/bookcraft/skills/makebook/fixtures/bind/run.sh:180-187`

It passes whenever the words "broken mid-word" are absent from the bind's output. Two failures
beyond the header's font-metrics caveat leave them absent: the warning at `build-book.py:3502-3504`
is reworded, or the broken-word detector goes blind. `plan_columns` (`build-book.py:1899`) repairs
only a table whose `broken` list is set, which is the same list that raises the warning, so a blind
detector skips the repair and silences the warning together. Words would print broken while the
check reports "repaired": the symptom this branch exists to catch.

Suggested fix: assert on the PDF as well. Each of the three long words must appear whole in the
appendix-table book's text layer, and the warning check stays as the explanation. The reviewer
confirmed on macOS that the pre-#39 binder prints none of the three words whole and the current
binder prints all three; Linux needs one CI run to confirm.

### Suggestions

**2. Two helper steps hide their own errors.**
- `run.sh:135-140`: the `book.json` edit's exit status is unchecked. A failed edit binds without a
  `cover_image` and reports a missing stamp, blaming the binder for a fixture fault. Use the
  `if ! "$py" - ... <<'EOF' ... EOF then report 1 ...; exit 1; fi` shape.
- `run.sh:149-154`: `2>&1 | grep` drops a Python traceback, so a corrupt EPUB reads as a missing
  stamp. Capture the output first, then grep it, and show it in the FAIL.

**3. Three doc phrasings are slightly off.**
- `.github/workflows/fixtures.yml:6-8`: "Without Chromium and poppler that fixture skips." It skips
  without the venv or `pdftotext`; a venv whose Chromium will not launch fails the bind.
- `README.md:149`: "without that toolchain" has the same nuance (optional).
- `plugins/bookcraft/README.md:363`: "binds four books" is four binds of three books.

### Deferred to follow-up

None new. The page-marker assertion is already under `## Deferred` in `PLAN.md`.

### Dropped

- The stamp check catches a per-cover `bind_stamp()` regression only when the two covers are
  stamped in different seconds; making that certain would mean faking the clock.
- `bind()` shadows bash's `bind` builtin: harmless in a non-interactive script.
- `mktemp -d` is unchecked: a failure still ends in a loud bind failure.
- `printf | grep -q` under `pipefail` can SIGPIPE on large input; the binder's output is ~1 KB.
- `LC_ALL=C` during the bind: no evidence it changes what the binder writes.
- The model-name bylines in fixture `book.json` files are createbook's documented cover byline
  from earlier work, not repo attribution, and this branch does not touch them.

## Questions

## Resolution (2026-09-25)

All three findings were fixed on the branch.

1. **Fixed.** The appendix-table check now reads the table's page back: it finds the appendix's
   page from its Contents line and requires `Denormalization`, `Characteristically` and
   `Referential` to print whole there, beside the unchanged warning check. Reading only that page
   keeps a word printed whole in an index from passing it. A mutant whose detector never records
   a break (so the binder neither repairs nor warns) fails the new check while the warning check
   stays silent, which is the gap this finding named. The pre-#39 binder fails both.
2. **Fixed.** The `book.json` edit is guarded and reports a fault in the fixture, shown with a
   simulated failure. The EPUB read is captured whole before filtering, so a missing
   `cover.xhtml` now shows its `KeyError` traceback.
3. **Fixed.** `fixtures.yml` and the root README say the fixture skips without the venv or
   `pdftotext` and fails when Chromium will not launch; the bookcraft README says three books,
   the guide twice.

`/bin/bash` 3.2 parses and runs the fixture, 12 of 12.

The review's question is answered: a throwaway branch with the pre-#39 binder (CI run
36141024240, branch deleted) failed the whole-word check on both legs, so Linux's `pdftotext`
also splits the three words and the check tests the repair there too.
